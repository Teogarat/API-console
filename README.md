# iiko API Console

Статическая консоль iiko Cloud, Yandex Eda и Magnit, без сборки. Откройте `index.html` или статический хостинг; запросы идут через выбранный Proxy Worker.

## Аудит iiko API — 10 ноября 2026

Каталог пересобран из [официальной OpenAPI](https://api-ru.iiko.services/api-docs/docs): **361 актуальная операция**. Из опубликованных 418 операций исключены 57 `deprecated`; два исторических запроса из старого HTML также не сохранены. Ни отключённая `/api/1/nomenclature`, ни старый `/api/1/access_token`, ни deprecated `/api/2/menu/by_id` больше не предлагаются для отправки.

Версия определяется конкретным контрактом. Актуальные `/api/1/organizations`, `/api/1/terminal_groups`, `/api/1/payment_types`, `/api/1/stop_lists`, `/api/1/deliveries/create` не переименовываются искусственно.

### Два независимых источника

**Без галочки — внешнее меню iikoWeb.** Список: `POST /api/2/menu` без тела. Загрузка: `POST /api/menu/v3/by_id` с `externalMenuId`, одним `organizationId` и `priceCategoryId` (либо `null`). Сохраняются размещения одного блюда, размеры, цены и группы модификаторов. В заказ идут реальные ID, а не внутренние ключи интерфейса.

**Галочка «Номенклатура v2 · без внешнего меню».** Загружаются:

- `POST /api/nomenclature/v2/product/list` — карточки;
- `POST /api/nomenclature/v2/group/list` — группы;
- `POST /api/nomenclature/v1/product-scale/list` — шкалы размеров, когда нужны. Этот v1-метод остаётся актуальным.

Используется пагинация `filters`, `limit`, `offset`, проверка повторов/неполных ответов и защита от ответа, пришедшего после смены организации/режима. Старый URL не вызывается в качестве fallback. Недоступность списка внешних меню не мешает отдельно читать номенклатуру. Ошибки доступа к номенклатуре показываются явно.

**Это не полная эквивалентная замена старой выгрузки меню:** справочник относится к контексту API-ключа; его list-контракты не принимают `organizationId`. Поле `defaultSalePrice` — базовая цена карточки, не подтверждённый тариф выбранного ресторана. Для тестового заказа из простых карточек требуется отдельное подтверждение организации и базовых цен. Для просмотра оно не нужно.

Размерные продажные цены не рассчитываются из коэффициентов списания. Неизвестные цены остаются `null`, реальная нулевая цена — `0`. Нераскрытая схема модификаторов, размерные цены, вложенные/делимые модификаторы и неподтверждённые бесплатные количества блокируют автоматический заказ, но не просмотр карточек. Для сложных позиций используйте внешнее меню или осознанно составленный JSON редактора. Список карточек может содержать товары/заготовки, не предназначенные для продажи: это справочник, а не витрина.

### Редактор запросов

Каталог включает точный метод, путь, описание, обязательные поля и редактируемый JSON. Пустые фильтры генерируются как `[]`, без неработающего `{field:"", op:""}`. Необязательные фильтры `ids` не заполняются случайными UUID. Для запросов без тела JSON не выдумывается.

Авторизация редактора использует v2 и данные приложения из настроек подключения; полученный токен применяется к следующим запросам. Секрет приложения не подставляется автоматически в текстовый редактор и маскируется в логах. Редактор iiko не отправляет запросы в режиме Yandex/Magnit. Ошибки сохраняют HTTP-статус, `errorDescription` и `correlationId`.

Шаблоны не являются готовыми операциями: реальные ID, даты, реквизиты и бизнес-параметры нужно заполнить. Наличие метода в OpenAPI не гарантирует права конкретного ключа, доступность сервера или применимость операции к выбранному ресторану. В режиме редактора можно намеренно менять данные ресторана; автоматические тесты этого не делают.

### Проверки

```bash
node --test tests/*.test.*
node scripts/check-api-contracts.mjs                 # только публичная OpenAPI
node scripts/check-api-contracts.mjs openapi.json    # сохранённый снимок, без сети
python tests/browser-smoke.py                       # требует Playwright и Chromium
```

Регрессионные тесты используют синтетические ответы. Браузерный тест открывает все 361 шаблон, переключает два режима меню, проверяет корзину и подтверждение базовых цен; `fetch` заменён синтетическим обработчиком. Никакие реальные заказы, оплаты или списания не выполняются. Живые запросы с ключом ресторана не проверялись.

Проверка контрактов сравнивает все записи и шаблоны с официальной спецификацией, а также прямые маршруты приложения. Она намеренно обнаруживает изменения спецификации, а не автоматически отправляет все методы.

### Обновление каталога

Node.js 20+; npm-зависимости не нужны:

```bash
node scripts/update-api-catalog.mjs --output catalog.json
node scripts/update-api-catalog.mjs --write-html
node scripts/update-api-catalog.mjs --input openapi.json --write-html --retrieved-at 2026-11-10T17:42:28Z
```

Генератор сохраняет источник/дату/хеш и исключает deprecated-операции. Изменения моделей ответа требуют отдельных правок загрузчика. Вендорные контракты Yandex/Magnit не входят в iiko OpenAPI и этим аудитом не сертифицированы; их загрузчики не переписывались.

Прокси по умолчанию: `Teogarat/yandex-proxy`, маршрут `api/proxy.js`. По просмотренному коду он передаёт произвольный относительный путь на выбранный фиксированный хост iiko; отдельный allowlist только для `/api/1` отсутствует. Развёрнутый экземпляр прокси и права реального ключа требуют отдельной проверки.
